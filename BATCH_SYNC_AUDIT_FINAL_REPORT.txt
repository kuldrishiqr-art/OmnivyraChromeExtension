ISSUE #2: API PAYLOAD STRUCTURE MISMATCH
────────────────────────────────────────────────────────────────────────────────
Severity:    🟠 HIGH - API unable to parse requests
Type:        Implementation Error
Files:       apiClient.js, syncEngine.js

Problem:
  Original implementation:
    - sendSyncEvents() accepted array of events
    - Sent batch of 5 events in ONE HTTP POST request
    - Payload: { events: [event1, event2, event3, event4, event5] }
    - Audit requirement: "SINGLE event per request (NOT array)"
  
  This caused:
    - API receives unexpected array structure
    - Backend payload parsing fails
    - Cannot track which event failed
    - Idempotency not guaranteed per-event
    - Retries unclear (retry entire batch or individual event?)

Root Cause:
  Original design optimized for fewer network requests
  Audit requirements specify individual event POSTs

Fix Applied:
  Modified apiClient.sendSyncEvents() to:
    1. Accept array of events (same input)
    2. Send EACH event individually via separate POST
    3. Each POST contains single event object (not array)
    4. 500-1500ms delays between individual requests
    5. Per-event error tracking
    6. Returns: {success, sentCount, failureCount}
  
  Simplified syncEngine.sendEvents() to:
    - Delegate to apiClient (removed batching logic)
    - No longer chunks into groups of 5
    - apiClient now handles individual sends + delays

Code Changes:
  
  BEFORE (Wrong):
    POST /api/extension/events
    {
      "events": [
        {platform: "linkedin", ...},
        {platform: "linkedin", ...},
        {platform: "linkedin", ...},
        {platform: "linkedin", ...},
        {platform: "linkedin", ...}
      ]
    }
  
  AFTER (Fixed):
    POST /api/extension/events #1
    {
      "platform": "linkedin",
      "event_type": "comment",
      "platform_message_id": "msg_abc",
      ...
    }
    
    [500-1500ms delay]
    
    POST /api/extension/events #2
    {
      "platform": "linkedin",
      "event_type": "comment",
      "platform_message_id": "msg_def",
      ...
    }
    
    [500-1500ms delay]
    ... (continues for each event)

Benefits:
  ✅ Matches audit requirement: "SINGLE event per request"
  ✅ Each event independently tracked
  ✅ Clear failure attribution
  ✅ Idempotent per-event sends
  ✅ 500-1500ms human-like delays between requests
  ✅ If event 3 fails, events 1,2,4,5 still sent

Verification:
  ✅ apiClient.sendSyncEvents changed to individual sends
  ✅ Delays implemented with randomDelay(500, 1500)
  ✅ Per-event error tracking
  ✅ successCount, failureCount returned
  ✅ syncEngine simplified (delegates all sending)
